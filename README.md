# fly-review

**Real fly wiring. Questionable judgment. Executable evidence.**

Would you merge code reviewed by a fruit fly?

fly-review gives a connectome-based neural simulation a vote on a code change, then teaches it from executed test outcomes the way a fly is taught: with a taste. It has **176,422 simulated neurons**, a real mushroom body, and no training except what executed tests give it: 522 lessons from two corpora whose labels were proven by running code (mutants of three real TypeScript repositories that their own suites killed, and small drafted scenarios executed against a reference), plus whatever you teach it on the page. Jev describes the change with thirty neutral questions, two of which the fly never smells because they ask whether behavior changed, which is the tests’ job; the rest of the description and the changed tokens become an odor. Then an independent investigator, shown neither the spec nor the vote, bets on one input, and ordinary code executes it. If it reproduces a regression, the fly tastes bitter while it smells the change; if a designated harmless control holds, it tastes sugar. Its own dopamine neurons fire, and the synapses that weaken are the ones the connectome puts under them. Its approval is its behavior: when a smell alone makes its proboscis motor neurons fire, the fly reached for it.

**Jev describes. The fly smells, tastes, and remembers. Tests check, and teach.** Bring a bundled example, paste a change, or point it at a real GitHub pull request, which the fly reads hunk by hunk and looks at the hunk that smells unlike the rest.

Four things this README says plainly because they are true. Nothing upstream of the fly says whether a change is good or whether it changed behavior: the two of Jev's thirty questions that came close ("restructures only", "renames only") are silenced, because one of them alone sorted 296 of 301 held-out changes and made the fly a middle-man (*The answer-key test*). Through the nose that's left, the fly decides, and it decides moderately well: 88.3% balanced accuracy on 301 changes it never saw, where chance is 50%, right 256 times in the 282 it votes on, with 25 bugs waved through. It is replaceable: a logistic regression reading the same smell gets 94.8%, so as a classifier of one change you could swap the fly for a spreadsheet. And the vote is the fly's own: rewire which dopamine neuron reaches which output neuron, degrees preserved, teach the rewired fly the same lessons through the same nose, and it catches 1 of 234 regressions and reaches for 212 of them; rewire which Kenyon cell reaches which output neuron and (measured through the earlier nose) nothing changes. A second circuit, novelty, reads a diff hunk by hunk and finds the one thing unlike the rest a little better than chance, 11 times in 40 against 6.7.

## The 30-second version

> Jev reads a code change and answers thirty descriptive questions about it. The two that ask whether behavior changed are switched off, because that is the test’s job; the other answers, and the tokens that changed, become an odor. The odor runs through a simulation built from real fruit-fly wiring. Then a separate AI, shown neither the contract nor the verdict, bets on one input, and code executes it against both versions. If it reproduces a regression, the fly tastes bitter while it smells the change; its punishment dopamine neurons fire and weaken the synapses the wiring puts under them. If a known-harmless control holds, it tastes sugar. The fly doesn’t understand TypeScript. It remembers what it tasted with a smell, and when a smell alone makes its proboscis come out, that is its approval. Give it a pull request and it reads hunk by hunk; every smell it is exposed to gets a little more familiar, so whatever still smells new on the second reading is where it looks.

```mermaid
flowchart LR
    D[Change or pull request] --> J[Jev describes<br/>thirty neutral receptors]
    D --> L[Changed tokens<br/>lexical receptors]
    J --> O[Odor<br/>53 glomeruli]
    L --> O
    O --> K[Kenyon cells<br/>sparse odor code]
    K --> M[MBONs by compartment<br/>avoid vs approach]
    M --> B[Proboscis motor neurons<br/>reached, or stayed still]
    O -.->|a pull request:<br/>one odor per hunk, read twice| N[α'3 novelty MBONs<br/>which hunk still smells new]
    D --> T[Claude bets on one input<br/>blind to contract and vote]
    T --> X[Code executes both versions<br/>plus a deterministic sweep]
    B --> E[Vote meets evidence]
    X --> E
    X -->|regression: bitter on the tongue<br/>control: sugar| DA[PPL1 / PAM dopamine neurons fire]
    DA -->|weaken KC → MBON synapses<br/>where the wiring delivers dopamine| M
```

## Run it

Requires **Node.js 24+**. Live Jev needs a [TypeSafe](https://docs.typesafe.ai/) key; the investigator needs an [Anthropic](https://console.anthropic.com/) key. Pull requests need nothing for public repos, and `GITHUB_TOKEN` or a logged-in `gh` for private ones and for posting.

```sh
npm install
npm run setup
test -f .env || cp .env.example .env   # then add your keys
npm run demo
```

Open **http://localhost:4488**.

0. New here? **Walk me through it** (top right, or open the page at `/#tour`) runs an interactive walkthrough on the real page: it swoops onto the mushroom body, shows Jev sniffing, the smell waking memory cells, two MBON teams pulling on the vote, the zap and the treat, and waits for you to ask the fly for real. Measured values are distinguished from clearly labeled illustrative numbers.
1. Choose a change and click **Ask the fly**. Jev describes it, the description becomes an odor, and 176,422 neurons run for 450 ms of simulated time. A fly that has learned nothing abstains.
2. Watch the recorded activity play back in 3D. The six ringed cells are the readout neurons. The fly in the corner is a lit, procedural 3D model (ellipsoids and tapered tubes at the animal’s proportions, faceted compound eyes, banded cuticle, veined translucent wings; a layered drawing if WebGL is missing) and shows what their firing does to the animal: MN9 extends its proboscis, DNg62 makes it groom, DNp01 raises its wings to jump. It reacts within a frame of each 25 ms bin. Click it to poke it. The vote is stamped on the diff when the bins finish.
3. Click **Was the fly right?** to run the investigation. A reproduced regression punishes the fly for this smell; a designated control rewards it. Then **Ask the fly again**: same change, same description, same seed; compare the new measured vote. **Forget everything** resets current memory, not the displayed recording. Ask again to measure the naive fly; a lesson is not a guarantee of a verdict change. **Ask another fly** gives a different seed the same memory.

Setup verifies and downloads the ~23 MB connectome, compiles the Java bridge, and exports the anatomy. It uses an existing JDK 21+ or downloads a project-local one on macOS/Linux arm64/x64. Nothing is installed globally. The simulation runs on your CPU; the browser uses WebGL with a 2D fallback. Turn **Sound on** for the spike crackle driven by the recorded bins, a ping per readout population, and the stamp.

| Action | What it costs |
|---|---|
| Ask the fly | One Jev request, then a local simulation (about 2 s) |
| Was the fly right? | One Anthropic request, then local code execution |
| Ask another fly | Nothing. Same description, new seed, new simulation |
| Fetch or post a pull request | GitHub API calls, unauthenticated for public repos |
| Replay, disconnect, rerun saved signals, tests, calibration | Nothing |

Defaults are `jev-latest` and `claude-haiku-4-5`; override with `TYPESAFE_MODEL` and `ANTHROPIC_MODEL`. `PORT` changes the port. Set `FLY_REVIEW_DATA_DIR` to a separate directory (for example `.runs/verification`) when running a second server, so its memory, record, and evidence are isolated. Without a TypeSafe key, live Jev is off; you can explicitly select **manual inputs** inside **Inspect this experiment**, which still runs the real simulation and is labeled as human-set. Nothing is silently mocked.

## Bring your own pull request

Pick **Review a GitHub pull request…**, paste a URL like `https://github.com/owner/repo/pull/123` (or `owner/repo#123`), and click **Fetch**. The page shows the title, description, and the whole diff, file after file with a sticky header per file, exactly as the encoder will see it. Then **Ask the fly**.

- The pull request is split at its `@@` hunks (up to 32; past that, whole files are the units, and past 32 files the largest 32). Jev describes **each hunk on its own**, with the title and description as context, within a **60 KB budget** (12 KB per file). Lockfiles and build output are listed by name with the patch omitted, as are binaries and renames without content changes. Each file header says whether its patch was shown or why it was not, and the same list is saved in the evidence bundle.
- The fly **reads the hunks in order, then reads them again**. Each reading makes a smell more familiar (see *Where it looks*); on the second, frozen reading, the hunk whose novelty MBONs stay loudest is the one it looked at. Its rows are tinted on the diff and marked; the list under the vote gives every hunk's novelty and avoidance share and scrolls to it on click. **The vote shown is its vote on that hunk.** A second opinion or a recall reuses the saved per-hunk descriptions and reads the whole diff again.
- **Nothing in the pull request is executed.** There is no contract, so there is no test: the fly votes and the vote stands untested. The bundled examples are where the vote is put on trial.
- Live Jev on a pasted change or a pull request shows the exact payload that would leave this machine (code and context, to api.typesafe.ai) and asks first. Cancel and choose manual inputs to keep the code local.
- With `GITHUB_TOKEN` or a logged-in `gh`, **Post the fly’s review to GitHub** leaves a comment-only review on the pull request: which hunk it looked at and why, the vote on that hunk, what Jev noticed, the mushroom body rates, how much memory the fly has, and a plain statement of what this is and isn’t. It asks first. It never approves or requests changes at the GitHub level.
- Private repositories work with a token that can read them.

You can also paste a single before/after file under **Paste your own change…**. Same rules: a vote, no test.

## What the fly actually does

**The nose is Jev.** Thirty descriptive questions, each a neutral yes/no property of the change (“changes a comparison operator”, “interpolates a parameter into a string”, “renames only”, “touches credentials”, …), each answered as a probability and each mapped to one olfactory glomerulus. None of them asks whether the change is good, but two came close enough to count as a verdict, and the fly never smells them: “restructures only” asks whether the change alters the computed result for any input, and “renames only” whether it alters computation, which is the label the tests produce. On the held-out split, “restructures only” alone sorted 296 of 301 changes, better than the fly did with it; a nose that can answer the test’s question makes the fly a middle-man, so those two glomeruli stay quiet (`VERDICT_RECEPTORS` in `src/review-odor.ts`, and *The answer-key test* below). The other 28 say what changed, never whether it broke anything. The remaining 23 glomeruli are lexical receptors: the identifiers and operators in the changed lines, hashed, with the background of keywords and punctuation adapted out. The result is an odor: a pattern of rates over the fly’s 53 glomeruli. The same description always produces the same odor, and similar changes smell similar. Jev’s descriptions of the same change wobble slightly between calls (measured on one example, three calls: at most 0.14 on one receptor, 93 to 96% of the same Kenyon cells, vote share 0.515 to 0.519), so **Ask the fly again** freezes the description and only the memory can differ.

**The odor code.** Each glomerulus’s projection neurons synapse onto a specific subset of the 4,064 Kenyon cells in the real wiring. The odor’s weighted input picks the 5% of Kenyon cells it drives hardest within each class (αβ, α′β′, γ), standing in for the APL neuron’s inhibition and giving every lobe a code. Two unrelated odors share about 1% of their cells; two odors sharing a glomerulus share about 40%. (The simplified antennal lobe in this LIF model saturates, so this stage is computed from the connectome rather than simulated; everything downstream is simulated.)

**The memory is in the compartments the wiring defines.** Kenyon cells synapse onto the mushroom body output neurons (MBONs) through 31,493 plastic synapses. Which MBONs count as *avoid* and which as *approach* is read from the connectome, not assigned by us: each compartment’s valence is set by the dopamine neurons that innervate it (Aso et al. 2014), so the 36 MBONs that receive more of their dopamine from PPL1 cells (the ones punishment recruits) drive approach, the 48 that receive more from PAM cells (the ones reward recruits) drive avoidance, and 4 α′3 MBONs carry novelty and no valence. The words are the literature’s; which cell wears which word is the wiring’s.

**A lesson is a taste, and the fly’s own dopamine neurons do the teaching.** After a reproduced regression, the same odor is presented again with bitter on the proboscis; after a designated harmless control, with sugar. The 16 PPL1 cells (bitter) or the 316 PAM cells (sugar) fire, and inside that run, every 5 ms, a KC → MBON synapse is weakened if its Kenyon cell has fired in the last 100 ms *and* the dopamine neurons the connectome wires onto that MBON fired this tick, by an amount proportional to how much of that MBON’s dopamine input they are. Which synapses can change, and by how much of the rate, is anatomy: PPL1 axons end on the approach compartments, so bitter weakens the odor’s pull toward approach; PAM axons end on the avoidance compartments, so sugar weakens its push toward avoidance. The rule never consults the readout labels. Two honest footnotes. The taste pathways into the dopamine neurons are incomplete in this model (sugar never fires PAM through the wiring, and bitter fires only some PPL1 cells), so each taste is paired with direct drive of its dopamine family at 200 Hz, disclosed in every receipt. And the form and rate of the plasticity rule are ours; the connectome has no synapse-level plasticity to read. What moved out of our hands is which synapses a lesson can touch, and how much dopamine each one sees.

**The vote is behavior first.** A naive fly never extends its proboscis to an odor. A fly that has tasted sugar with a smell does: the proboscis motor neurons (MN9) fire to the smell alone, 30 to 36 Hz, through the fly’s own MBON-to-motor wiring, and that is its approval. Objection has no motor expression in this model (the odor of a punished change silences the approach MBONs, but nothing downstream of them reaches the legs or wings at these intensities), so an objection is read from the MBON populations: avoidance share `avoid / (avoid + approach)` above 0.68 is *changes requested*; a share below 0.45 without a reach is a lean, reported as *no objection*; in between the fly abstains. A naive fly sits at 0.6 with its tongue in on everything.

**What teaches it.** Two things only. A regression reproduced by execution is bitter. A designated behavior-preserving control that the sweep could not fault is sugar. “No regression found” on anything else stays unknown and teaches nothing, because it is not proof of correctness. Pull requests and pasted changes have no contract, so they are smelled and voted on but never taught.

The taste is a statement about the smell, not a grade for the fly. As in Pavlovian conditioning, the outcome is paired with the odor whether or not the animal was already avoiding it, so a fly that backed away from a change whose regression is then reproduced is not being told it was wrong; the same bitter deepens a memory it already had. The page says which of three things happened: **Confirmed** (the vote and the test agree), **Corrected** (they disagree), or **Learned** (the fly had abstained). What this model leaves out: in real flies, MBON feedback onto dopamine neurons shrinks the teaching signal for a well-learned odor; here every pairing delivers the same taste for the same time.

**Does the wiring matter? The shuffle test** (`SHUFFLE=dan-mbon:1 npm run train`). The one test that could have come out either way: keep the encoding, the seed, the lessons, the rule, and the readout labels identical, and permute the postsynaptic targets of one class of edges among themselves so every cell keeps its in- and out-degree and only *who talks to whom* is destroyed. Then teach the rewired fly the same lessons and test it on the same held-out cases.

| Wiring | Held-out: regressions caught | Controls approved | Reached for controls | Reached for regressions | Bundled: agree | Reached for bundled controls |
|---|---|---|---|---|---|---|
| Real connectome | **13 / 15** | 35 / 41 | 34 / 41 | 1 / 15 | 11 / 15 | 4 / 7 |
| Dopamine → MBON edges shuffled | **0 / 15** | 25 / 41 | 25 / 41 | **11 / 15** | 6 / 15 | 6 / 7 |
| Kenyon cell → MBON edges shuffled | 13 / 15 | 36 / 41 | 35 / 41 | 1 / 15 | 7 / 15 | 4 / 7 |
| MBON output edges shuffled | 13 / 15 | 34 / 41 | 31 / 41 | 1 / 15 | 8 / 15 | **1 / 7** |

Through the live nose and memory (neutral, rate 0.05, three passes), the dopamine shuffle comes out the same way: the rewired fly catches **1 of 234** held-out regressions and reaches for **212** of them, against 193 caught and 25 reached for with the real wiring; on the bundled examples it catches 0 of 8 and reaches for all 8 (`data/training.shuffle-dan-mbon.neutral.json`; the untuned one-pass neutral fly's shuffle, 0 of 234, is `data/training.shuffle-dan-mbon.neutral-r0.1p1.json`). The table below was measured through the earlier, full nose.

With the dopamine neurons rewired onto random output neurons, bitter and sugar each weaken a random mix of compartments, the memory carries no valence, and the fly reaches for regressions as readily as for controls. Nothing in the encoding changed. If this row had matched the first, the connectome would have been decoration on a random projection, and this README would say so. The third row says something else, also true: rewiring which Kenyon cell reaches which MBON changes nothing held out (it drops the hand-written examples from 11 to 7 of 15). That is the mushroom body as the literature describes it: a random expansion of the odor onto Kenyon cells, whose identities are interchangeable, read by compartments whose meaning is fixed by the dopamine neurons that innervate them. The valence lives in the DAN → MBON wiring, and only there. The fourth row is about the body: rewire where the MBONs project and the MBON readout still classifies (the labels are unchanged), but the reach mostly stops on the hand-written examples, 1 of 7 instead of 4 of 7, because the path from the approach compartments to the proboscis is a particular set of edges and the shuffle scattered it; held out, enough of that path survives the permutation for 31 of 41. Each shuffle is one seed; the numbers are one draw each, not distributions, and this table was measured on the grown corpus alone (126 lessons). Repeated with the full corpus (522 lessons, rate 0.1), the dopamine shuffle comes out the same way: 0 of 234 held-out regressions caught, 195 of them reached for, 5 of 15 bundled (`data/training.shuffle-dan-mbon.grown-mined.json`). Evidence: `data/training.shuffle-dan-mbon.json`, `data/training.shuffle-kc-mbon.json`, `data/training.shuffle-mbon-out.json`.

**Where it looks: the α′3 compartment.** One mushroom body compartment encodes novelty rather than valence: its output neurons answer an unfamiliar odor and fall quiet as the odor becomes familiar, because exposure alone, through the dopamine neuron PPL1-α′3, depresses that odor's Kenyon-cell synapses onto them (Hattori et al. 2017). In hemibrain numbering that is MBON17 (MBON-α′3m, the class that shows the suppression; 4 cells here, kept out of the valence groups along with MBON16). A pull request is presented to it as a sequence: one puff of odor per hunk. During the reading pass, the α′3 compartment's own dopamine neurons (the 2 PPL1 cells whose MBON output lands mostly on MBON16 and MBON17) are driven with each puff, and the same in-run rule a lesson uses depresses the active Kenyon cells' synapses where that dopamine lands, by up to 30% per puff. Familiarity is a short-lived memory in the animal (Hattori et al. followed it over minutes to hours), so α′3 synapses are never written to the long-term memory file: what a lesson's dopamine does to them stays inside that run, and only the α′3 changes from a reading pass carry into the readout, so every hunk's valence is measured against the long-term memory alone, exactly as a single smell would be. Then every puff is presented again with those synapses frozen, and once more with them restored, so each hunk reports what it evoked on the second reading against what it would have evoked on first exposure. Every puff runs on a freshly built network with the same seed, so only the synapses carry over and the readout does not depend on hunk order. The hunk whose novelty MBONs stay loudest is where the fly looked, and when it stands out from the rest (at least half the hunks went quiet and it is at least half again louder than the median) that hunk's valence readout is the vote shown; when nothing stands out, the vote is the majority over every hunk's own vote. None of this touches the long-term memory: familiarity with one review is never saved. Novelty means *unlike the rest of this diff*, not *wrong*.

**The boring alternative** (`npm run baseline`). Could you skip the fly and look at the smells? A logistic regression over the descriptors as the fly hears them (the two verdict receptors silent), fit on the same training split, judged with the fly's own vote bands:

| Set | Fly | Logistic regression |
|---|---|---|
| 301 held-out cases (56 grown, 245 mined) | 256 (193/234 regressions, 63/67 controls, 1 false alarm, 19 abstained) | 268 (204/234 regressions, 64/67 controls, 1 false alarm, 23 abstained) |
| 15 bundled examples | 10 (4/8 regressions, 6/7 controls, no false alarms, 2 abstained) | 12 (5/8 regressions, 7/7 controls, 3 abstained) |
| 522 training cases | 453 | 475 |

Twenty-eight weights beat 31,493 plastic synapses by twelve cases held out and two hand-written. The strongest are `changesDefault` (+4.97), `changesReturnShape` (+3.14), `removesLogic` (+2.58), and `changesLiteral` (+2.57): descriptions of what changed, which the corpus turned into cues, because its harmless controls never change a default or a literal. As a classifier of one change, the fly is replaceable and worse. And the baseline has no wiring to shuffle: the test above is one it cannot take.

**The answer-key test** (`npm run nose`). The baseline above reads Jev's numbers; the fly reads an odor. To compare like with like, this reads the exact 53-glomerulus odor the fly smells, on the same split, and asks what the single best glomerulus gets alone (its threshold chosen on the training cases) and what a logistic regression over all 53 gets. Scores are balanced accuracy, the mean of regressions caught and controls approved, because three in four held-out cases are regressions and “always object” scores 78% raw; chance is 50%, and the fly's abstentions count against it.

| Nose | Best single glomerulus | Logistic, same 53 glomeruli | Fly |
|---|---|---|---|
| full (all thirty receptors; the earlier fly) | **98.4%** (`restructuresOnly`) | 99.1% | 93.4% |
| **neutral** (verdict receptors silent; the live fly) | 83.2% (`changesDefault`) | 94.8% | 88.3% |
| lexical (no Jev at all; hashed tokens only) | 63.1% | 77.4% | 46.3% |

The full and lexical flies were taught at rate 0.1 in one pass; the neutral row is the tuned live fly. Read the rows in order. Through the full nose one receptor was the answer key, and the fly scored below it: a middle-man. Through the neutral nose nothing upstream knows whether a change broke anything, and the fly decides; it beats the best single observation by five points and loses to a linear model by six and a half. (Before tuning, at the one-pass rate chosen through the full nose, it scored 84.5%: one point over the single observation; see *Training*.) Through tokens alone it learns nothing usable (46.3%, and 235 of its own 522 training cases), though a linear model finds 77% in the same tokens: the mushroom body's sparse code of 23 hashed glomeruli does not separate these classes, and the fly needs a nose that perceives structure. The neutral nose is installed. The full-nose fly is kept as `data/training.nose-full.json` and `data/trained-memory.nose-full.json`, the lexical run as `data/training.nose-lexical.json`. Evidence: `data/nose.json`.

**Where it looks, measured** (`npm run bench:attention`). Synthetic diffs are assembled from executed cases: five hunks sharing a smell category plus one odd hunk the fly was never taught, shuffled, forty diffs per direction. Random chance is 6.7 of 40.

Through the live (neutral, tuned) nose and memory:

| Diff | Fly looked at the odd hunk (novelty) | Fly valence | Per-hunk logistic |
|---|---|---|---|
| Odd regression among five controls | **11 / 40** (odd hunk 22 Hz, the rest 11 Hz) | 23 / 40 | 27 / 40 |
| Odd control among five regressions | 1 / 40 (odd hunk 11 Hz, the rest 23 Hz) | 31 / 40 | 38 / 40 |
| Odd control among five controls of another category | 3 / 40 (11 Hz vs 10 Hz) | 7 / 40 | 7 / 40 |
| Odd regression among five regressions of another category | 14 / 40 (31 Hz vs 25 Hz) | 18 / 40 | 22 / 40 |

The rows say what novelty is and is not. Controls that share a category smell alike, so they familiarize each other and fade (11 Hz after one reading), and the one regression stays louder: novelty finds it 11 times in 40, under twice chance, without knowing what a regression is. Regressions do not smell alike even within a category (23 to 25 Hz after a full reading), so little goes quiet and there is nothing for an odd hunk to stand out from; an odd control among them is the quietest hunk, not the loudest. Within a class, everything is near chance, for the fly and for the classifier alike, except that an odd-category regression among regressions stands out 14 times in 40. Novelty finds the one thing unlike the rest only when the rest are alike. That is the shape of a real diff's mechanical bulk (#249 below: sixteen of twenty-two hunks went quiet) and not the shape of five different bugs from five different files. Where the class of the odd hunk is what makes it odd, the classifier wins outright, as it should.

Silencing the verdict receptors cost novelty most of its edge. Through the full nose the first row was **21 of 40** (odd hunk 42 Hz, the rest 17 Hz), three times chance, with valence 34 and the per-hunk logistic 40 of 40 (`data/attention-bench.nose-full.json`, `data/attention-bench.same-class.nose-full.json`). Why the neutral nose loses it is not measured here. The untuned one-pass neutral fly found it 10 of 40 (`data/attention-bench.neutral-r0.1p1.json`). Under an earlier rule, in which one exposure multiplied the α′3 synapses by a fixed 0.7, the full-nose first row was 29 of 40 (`.runs/attention-bench.old-rule.json`); exposure through the α′3 dopamine neurons themselves depresses less per puff, and no rate was retuned to recover the number. Evidence: `data/attention-bench.json`.

**Memory on disk.** `.runs/memory.json` stores the learned synapse factors and the lessons that produced them in one file, committed together by an atomic write; the older two-file layout (`memory-log.jsonl`) is still read and migrates on the next lesson. Each lesson teaches a run-local staging copy first and commits with one rename. An exclusive lock serializes memory commits and resets across server processes; a changed baseline rejects promotion. Interrupted teaching reports the prepared receipt path for inspection rather than silently retrying. A stale `.lock` is not removed automatically: inspect its recorded PID and the saved receipts before recovery. **Rerun the exact saved inputs** and **Does the brain actually matter?** simulate against the memory the run started with, not whatever has been learned since. **Replay** only plays the existing recording. Receipts shown in the browser omit bulky geometry; the full recordings stay under `.runs/`.

**Calibration** (`npm run calibrate`) presents odors to a scratch memory and never sees an example. Naive shares 0.60 to 0.62 with the proboscis motor neurons silent; in an ordinary smell the dopamine neurons are quiet (PPL1 under 10 Hz, PAM under 1 Hz). Bitter with odor A fires PPL1 at 227 Hz and PAM at 0, and the depression lands 575 to 5 on approach over avoidance compartments (synapses weighted by the dopamine they saw); two bitter lessons send A to 0.94, leave an unrelated odor at 0.63, and move an odor sharing one glomerulus (42% of its Kenyon cells) to 0.78. Sugar with odor B fires PAM at 200 Hz and PPL1 at 22, the proboscis extends during the lesson (MN9 96 Hz), and the depression lands 578 to 75 on avoidance over approach; afterwards B alone makes the fly reach (MN9 36 Hz, share 0.32) where the punished odor still leaves it still. Runs are bit-identical; with synapses off, nothing fires. Eighteen checks, all passing, in `.runs/calibration.json`.

**The causal demonstration** works live: smell a change (abstain, tongue in), reproduce its regression (bitter: PPL1 fires, about 1,300 synapses weaken where its axons end), smell it again (changes requested), forget (abstain). Or the other way: smell a control, prove the sweep cannot break it (sugar: PAM fires, the proboscis comes out during the lesson), smell it again and watch the proboscis come out to the smell alone. Same change, same frozen description, same seed; only the memory differed. A control that shares a function with a punished bug starts out leaning toward objection because it smells similar, and its sugar corrects that.

**Two corpora, both labeled by execution.** Fifteen hand-written examples cannot teach a nose much, so the corpus is grown two ways, and in both the label comes from running code, never from a person or a model saying so.

*Grown* (`npm run grow-cases`): Claude drafts scenarios, a small pure function, a prose contract, an independent reference implementation, the original, and changed versions it labels as regressions or behavior-preserving controls, across fourteen smell categories (removed guard, boundary flip, off by one, rounding, unit mismatch, swallowed error, boolean logic, constant return, leaked secret, changed default, string handling, clamping, null handling, precedence). Nothing it says is trusted. Every variant is executed against the reference over up to fifty fixed inputs, and only variants whose label the harness proves are kept: a claimed regression must actually break the contract on a valid input, a claimed control must survive every input, and a scenario whose original disagrees with its own reference proves nothing. Of 95 drafts, 29 were rejected outright and 82 variants were dropped by execution; 182 cases remain in `data/grown-cases.json` (78 regressions, 104 controls).

*Mined* (`npm run mutate:repo -- owner/repo`): real code, judged by its own tests. The tool clones a TypeScript repository, installs it with scripts disabled, runs its suite once and refuses to continue unless it is green and type-checks, then runs [StrykerJS](https://stryker-mutator.io) with the repository's own runner (vitest or jest, per-test coverage, the TypeScript checker on so mutants that would not compile are discarded rather than counted). Every mutant the suite **kills** is a change that made a real test fail: bitter. The mutation and the function it sits in are cut out as before and after, up to three per function, spread across mutation kinds, with an emptied `{}` body taken last because no reviewer ever sees one. For sugar, the same functions get mechanical rewrites (invert an `===` into a negated `!==`, flip an if/else, write a comparison the other way round, rename a local) applied to the working tree in batches and kept only when the type check and the whole suite pass; a failing batch is bisected. Comparison rewrites come first so the nose cannot learn that touching a comparison means bad. Survived and uncovered mutants teach nothing: a change the tests missed is unknown, not safe. Three repositories so far, `data/mined/*.json` with a summary beside each:

| Repository | Suite | Mutants killed | Functions | Kept as regressions | Rewrites verified (rejected) | Stryker time |
|---|---|---|---|---|---|---|
| `workos/authkit-nextjs` | vitest, 420 tests | 892 | 78 | 203 | 103 (1) | 6 min |
| `workos/authkit-js` | jest, 324 tests | 285 | 36 | 91 | 50 (1) | 8 min |
| `unjs/ufo` | vitest, 978 tests | 633 | 50 | 123 | 71 (0) | 2 min |

Two rejected rewrites were renames the suite caught (a test asserted on the variable's name through a mock), which is what verification is for. The mining runs a stranger's `install` and tests on your machine; only mine repositories you would run locally. What it cannot give you is the distribution of real bugs: an empirical study of TypeScript bugs (TSBugs, 633 instances) finds them dominated by tooling and configuration, API misuse, and type errors, none of which a mutation of one expression resembles. This corpus teaches what a broken comparison, a dropped guard, a wrong literal, and a removed call smell like in real code, next to matched harmless edits of the same functions.

**Training** (`npm run train`) teaches a fresh fly equal numbers of bitter and sugar lessons from both corpora (261 each, interleaved; the live fly takes three passes over them), holding out a fifth by *family*, a grown scenario or one function of one repository, so sibling mutants of one function never straddle the split. The fifteen bundled examples are never taught. Through the full nose, rate mattered with this many lessons: at 0.3, the rate that suited 126 lessons, 522 of them depress shared synapses until the mushroom body barely answers (69 quiet abstentions, held out 283 of 301, bundled 9 of 15); at 0.15 there are 3 quiet abstentions and at 0.1 none, both held out 290 of 301 and bundled 12 of 15. Between those two, the wobble test decides (`npm run wobble`): Jev's description of one change moves by a few hundredths between calls, so each bundled example's cached descriptors are jittered by ±0.03 four times and the votes compared. At 0.15 four of fifteen cases change verdict under that jitter; at 0.1, two (`discount` and `flip-equality`, both sitting near a line), so 0.1 was chosen. That choice was made through the full nose. Through the neutral nose it was tuned again, without touching the held-out families: a seeded fifth of the *taught* families (133 cases in 35 families) was held back as a validation slice, six settings were taught on the rest (`VALIDATE=0.2 npm run train`), and the best on validation was retrained on all 522 lessons and tested on the held-out cases once. Validation balanced accuracy: rate 0.05 with three passes 89.6%, rate 0.1 with two 88.9%, rate 0.2 with one 88.0%, rate 0.1 with one (the earlier setting) 83.4%, rate 0.05 with two 81.0%, rate 0.1 with three 79.3%. The top three are within two points on 133 cases, so the choice among them is close to noise; the rule, best on validation, was fixed before the runs. The live fly is rate 0.05, three passes (`data/training.json`; the one-pass fly is kept as `data/training.neutral-r0.1p1.json`; the sweep's runs and pick in `.runs/tune/`). The proboscis is the fragile part: in a fly this well taught, the mushroom body answers at a third of its naive rate, and whether that reaches the tongue is a threshold crossing that 0.03 of description can tip. All runs are kept (`data/training.json` for the live neutral nose, `data/training.neutral-r0.1p1.json` for its untuned predecessor, `data/training.nose-full.json` for 0.1 through the full nose, `data/training.rate0.15.json`, `data/training.rate0.3.json`; the grown-only run at `data/training.grown-only.json`).

**What the trained fly can and cannot do.** Through the neutral nose, tuned, on 301 held-out cases in 44 families it agrees with execution 256 times (a naive fly, 0): 193 of 234 regressions caught, 63 of 67 controls approved, 1 false alarm, 25 regressions approved, 19 abstentions; when it votes, it agrees 256 times in 282. Split by corpus: grown 36 of 56 (18/36 regressions, 18/20 controls, 7 abstentions), mined 220 of 245 (175/198 regressions, 45/47 controls, 12 abstentions). The body's own vote: it reached for 63 of the 67 held-out controls and for 25 of the 234 regressions. Renames it reaches for 25 of 25 without a receptor that says "renames only"; equality inversions it approves 12 of 14, if/else flips 6 of 6, swapped comparisons 2 of 2. Against the untuned one-pass fly (200 caught, 56 approved, 15 regressions approved, 29 abstentions) the tuned fly abstains less, approves more harmless changes, and waves more bugs through: the gain in balanced accuracy is mostly on the approval side. On the fifteen bundled examples, written by a person before either corpus existed, it agrees 10 times: 4 of 8 regressions caught (`search-race` 0.93, `retry-delay` 0.91, `agent-tools` 0.81, `audit-log` 0.70), 6 of 7 controls approved (`refactor`, `leg-count`, `document-total`, `shorter-names`, `name-threshold` reached for at MN9 28 to 32 Hz; `template-line` at 0.43 without a reach), no false alarms, two abstentions (`token-expiry` 0.58, `flip-equality` 0.68), and three regressions approved and reached for: `rounding` (0.48, MN9 30 Hz), `discount` (0.54, MN9 30 Hz), and `retention` (0.59, MN9 32 Hz), the failures to show on stage. Through the full nose it scored 12 of 15 here; the difference is what the answer key was doing. The largest gaps the neutral nose reports between the classes are `changesDefault` (0.10 on controls, 0.50 on regressions), `removesConditional` (0.13, 0.48), and `removesLogic` (0.16, 0.52): what changed, not whether it broke. `npm run train` prints the per-receptor gap as the nose hears it, so this is measured, not assumed.

**Intended changes: the test that says what it learned** (`npm run intent`). Every harmless lesson is a refactor, so in the corpus "harmless" and "behavior unchanged" are the same thing. This set separates them: 24 hand-written tickets that change what a function should do (free shipping from $50 instead of over $100, trials of 14 days instead of 7, hotfixes deploy without approval), each with a new written contract, an independent reference implementation, and two changes of the same kind and size: one that does what the ticket asks and one plausible mistake implementing it (`>= 5000` against `> 5000`, `padStart` against `padEnd`). Every label is proven by executing both against the reference before anything is scored, and the set was scored once against the trained fly the talk quotes (`data/intent.json`; the script refuses to re-score without `FORCE=1`). Jev saw the new contract with each change. The fly approved **0 of 24** correct changes and objected to 23; it caught 22 of 24 mistakes; it gave both changes of a ticket the same verdict 22 times in 24. Balanced accuracy 45.8%, below a coin flip. The logistic regression on the same odor scored the same 45.8% (2 of 24 correct changes approved, 20 of 24 mistakes caught). So what the fly and the classifier learned from this corpus is *did behavior change*, not *is the change right*: on the held-out exam those coincide, because every behavior change in it is a bug. Telling a right behavior change from a wrong one needs the intent, and nothing in the odor carries it. Two checks rule out the obvious objections. The set is not simply strange to the fly: a behavior-preserving tidy-up of each right change (swap a comparison, name a value, invert a ternary; `CHECK=refactor npm run intent`, `data/intent-refactor.json`) was approved 22 of 24 times, with 0 objections and the proboscis out on 19; the spreadsheet approved all 24. And real pull requests agree: of the authkit-nextjs source hunks in `data/pr-smells.json` (the six most novel per pull request), the fly objected to 10, was unsure of 7, and approved none; its pull-request-level approvals came from documentation, test, and configuration hunks. The limit is in the pipeline, not in fly neurons: no receptor asks whether a change satisfies the stated contract (Jev is told not to judge), and no lesson ever rewarded a change that altered behavior. Scored on one seed.

**On real pull requests.** `npm run smell:prs -- owner/repo#N …` smells pull requests against a memory without teaching anything; `ATTENTION=1` also reads each one hunk by hunk. Eight merged pull requests from `workos/authkit-nextjs`, including the two later reverted (#249 and #35), against the installed fly. Smelled whole through the neutral nose, the tuned fly objects to one: #35 (0.72), the callback-route change that was reverted. It abstains on #454 (0.63) and has no objection to the other six, the three documentation changes (#486 0.50, #249 0.50, #483 0.43) and three code changes (#476 0.53, #467 0.47, #455 0.52). The untuned one-pass fly drew the same lines (`data/pr-smells.neutral-r0.1p1.json`). None is reached for. Through the full nose it objected to four of the five code changes and abstained on the documentation (`data/pr-smells.nose-full.json`): taught bitter on 203 mutants of this repository's functions, with renames and comparison rewrites as its only sugar there, it smelled any feature as a mutant. Without the answer key, ordinary feature code no longer smells like one; the fly also no longer objects to #249, whose bug was in its mechanical edits. The logistic baseline on the same descriptors objects to #35 and #454, abstains on four, and approves #249 and #467. Earlier flies are kept too: grown-only abstained on four and objected to four, with the README rename #483 as a false alarm (`data/pr-smells.grown-only.json`); the one before that, on a code that took the top 5% of all Kenyon cells at once, approved seven of the eight including both reverts (`data/pr-smells.before-class-code.json`).

Read hunk by hunk, #249 (“fix ESM import extensions”, 22 hunks) is the instructive one. Sixteen of its hunks went quiet on the second reading, most of them the same mechanical edit; the fly looked at `.eslintrc.cjs` (33 of 85 Hz), then a README hunk and `package.json`, the hunks unlike the rest. The bug that got #249 reverted (#268, a Next.js middleware failure) lived in the mechanical edits themselves. Novelty found the odd hunks and pointed away from the systematic one: that is exactly what “unlike the rest” means and exactly its failure mode, and a reviewer who looks only where the fly looks would have missed this one. On six of the other seven, fewer than half the hunks went silent, so nothing stood out, and voting on the loudest of sixteen hunks that are each new in their own way would be arbitrary. So when nothing stands out the vote is the count: every hunk gets the same vote a single change would, and a majority of one verdict is the verdict (#482, 16 hunks, through the full nose: changes requested on 11, no objection on 1, abstained on 4, so "Nothing stood out. Changes requested on 11 of 16 hunks."). The page still names the loudest: #455 (7 hunks) was loudest at the third hunk of `src/authkit-callback-route.ts` (39 of 117 Hz); #454’s loudest hunks stayed at 26 to 33 Hz of their 76 to 94 on first exposure. The page never presents an untaught case's vote as a considered verdict: under the vote it says which hunk it looked at and why, or that nothing stood out and how the count went, lists every hunk's novelty, share, and vote, and names the taught odors this one resembles most. Evidence: `.runs/pr-smells.json`, `data/pr-smells.json`.

**Install and forget.** `npm run memory:install` makes `.runs/trained-memory.json` the live fly (factors and lesson provenance together, under the memory lock; `npm run memory:install -- data/trained-memory.json` installs the checked-in copy, whose report is `data/training.json`); a running server reads the file fresh on its next smell. **Forget everything** erases training too; install again to restore it. `npm run learn` still runs the older leave-one-out over the bundled examples alone (4 of 15 after one pass), which is the measurement the trained corpus was built to improve on.

**Earlier encodings.** Two previous encodings are recorded under `.runs/`: a neutral four-property mixture that scored 10 of 20 and objected to every rename, and a valenced six-judgment mapping that scored 18 of 20 by having Jev decide what was good and bad. The second was abandoned because the fly contributed nothing but a mapping we chose. The third, the full thirty-receptor nose, is kept as `data/training.nose-full.json`: none of its questions asked whether a change was good, but one asked whether it altered the result for any input, and that answer alone outscored the fly. This version silences it so the fly’s vote is its own.

### Poke the fly

The drawing in the corner of the brain view is interactive. Click a body part, or one of the buttons under it, and the simulation stimulates that real sensory population directly, no code and no Jev, and records what reaches the six readouts. It is the fastest way to learn what the three channels mean:

| Poke | Population (annotated class in the connectome) | What happened at 150 Hz, seed 7 |
|---|---|---|
| Sugar on the labellum | 42 labellar and pharyngeal sugar GRNs | A 60 Hz: proboscis extends |
| Bitter on the labellum | 57 LB1 gustatory neurons | nothing fires; with sugar present, MN9 drops from 60 Hz to 0 |
| Deflect the antennae | 540 Johnston’s organ wind/gravity/grooming neurons | B 196 Hz: grooming |
| Looming shadow | 311 LC4 + LPLC2 looming detectors | C 478 Hz: wings up |
| Sugar on the feet | 768 tarsal gustatory bristles | nothing downstream |
| Smell of mold, puff of CO2 | 48 geosmin ORNs, 55 CO2 ORNs | a little feeding drive, no aversion in this model |
| Smell of fruit | 410 food-odor ORNs | A 30 Hz |
| Pheromone (cVA) | 334 DA1 + VA1v ORNs | A 52 Hz |
| Flash of light, brush the bristles, tap the abdomen | 3,377 / 2,206 / 1,145 neurons | activity, no readout response |

One modality at a time, each readout answers alone. Pokes go in through the sensory neurons; reviews go in as odors to the mushroom body; lessons go in as both, a taste on the labellum while the odor is on. Bitter on the labellum fires 10 of the 16 PPL1 dopamine neurons through the fly’s own wiring (74 Hz at 150 Hz of bitter); sugar reaches none of the 316 PAM cells, whose gustatory input falls below the connectome’s five-synapse threshold, which is why a lesson tops each family up directly. All of it runs the same network.

Each seed is a different fly with a name. **Ask another fly** keeps Jev’s description and the memory and changes only the seed. **Ask the fly again** keeps the seed too, so the only thing that can differ is what it has learned since.

### Cross-examine the fly

Under the verdict, **Cross-examine the fly** runs local experiments with no model calls. **Smell the same change again** re-presents the frozen odor with the same seed against the current memory and keeps a history of every measured vote for that odor. **Compare with no memory** runs the same odor and seed against an explicit empty memory alongside the current one, without erasing or teaching anything; that measures the effect of the whole memory, not of one lesson, and a vote that does not change is a result too. **Compare familiar smells** reports Kenyon-cell overlap between this odor and saved lesson receipts. Overlap is recorded odor-code similarity, not causal attribution, and receipts from incompatible earlier encodings are reported as unavailable rather than as zero overlap.

A lesson is a measured change in the memory. It is not a promise that the next vote crosses a line; the page shows the share before and after and lets you compare.

**Sugar, then bitter.** After a sugar poke, **add bitter** presents both with the seed, intensity, and memory held constant, so the drop from 60 Hz to 0 is attributable to the bitter neurons alone.

### The investigation

A review comment is a hypothesis. For the bundled examples, **Was the fly right?** turns it into evidence:

1. Claude receives the diff, the argument domains, and the caller context. **Not the written contract. Not the fly’s vote.** It infers the intent and bets on one input.
2. The harness executes the original and the changed function on that input and on a case-specific deterministic sweep, and judges every result against the contract, implemented independently. The model’s expected value is never the oracle.
3. The receipt says who found what: **the investigator found it blind**, or **the investigator missed and the sweep found it**, or nothing was found.

| Result | Meaning |
|---|---|
| **Confirmed** | A valid input satisfies the contract before the change and fails after it |
| **Unsubstantiated** | No regression demonstrated in the executed cases; not proof of correctness |
| **Inconclusive** | The original did not satisfy the contract, so nothing can be attributed |

**Copy the regression test** gives you a runnable assertion that fails against the changed implementation. Every review writes a local evidence bundle under `.runs/review-…/` with the inputs, the neural recording, the vote, the verification, and (for pull requests) `pull-request.json`, `pull-request.diff`, and the posted comment.

## What is real and what is ours

Real: the wiring (a processed derivative of the male fruit-fly CNS connectome, 176,422 neurons and 6,287,749 retained connections), which Kenyon cells each glomerulus reaches, which KC → MBON synapses exist to be depressed, which dopamine neurons reach which MBON and therefore which synapses a bitter or a sweet taste can change, which MBONs count as approach or avoidance (the compartments PPL1 innervates against the ones PAM innervates), the path from MBONs to the proboscis motor neurons, the neuron positions in the 3D view, the leaky integrate-and-fire simulation over that graph, the recorded spikes, and the executed test results.

Ours: the thirty questions, which two of them count as verdicts and are silenced, which glomerulus each drives, the token hashing, the 5% Kenyon-cell selection, the ×5 on KC → MBON synapse strength that lets the odor code drive the MBONs, the form of the plasticity rule (a synapse from a Kenyon cell active in the last 100 ms weakens each 5 ms tick by the rate times the share of its MBON’s dopamine neurons that fired) and its rates (0.6 for a lesson on the page; for bulk training 0.05 over three passes, chosen on a validation slice of the training families; 0.3 per exposure for familiarity), the 200 Hz drive that tops up the dopamine neurons because this model’s taste pathways into them are incomplete, the choice of bitter and sugar on the proboscis as punishment and reward, MBON17 as the novelty readout (Hattori 2017), one reading pass before the frozen readout, splitting a pull request at its hunks, the 0.45 and 0.68 lines and the 8 Hz reach line, and the words “changes requested”, “no objection”, “reached for it”, and “looked here”. The score is not a probability of a bug. A network that participates is not a network that understands; **Does the brain actually matter?** disables synaptic transmission with the same inputs and seed and shows the readouts go silent, which demonstrates participation and nothing more. The shuffle test above is the sharper instrument: it shows the vote depends on which cell is wired to which. There is no pretraining for code review, no biological validation of this use, and no claim about consciousness. Only explicitly executed teaching trials change the saved memory.

The visualization is downsampled (6,087 soma positions, 1,600 sampled connections, the top 100 spiking neurons per bin, all six readout neurons). Lines are straight soma-to-soma segments, not axons. The signal rail entering the scene is a diagram. Camera movement is not activity. The fly drawing moves only the parts those three populations control in a real fly; its “hungry and alarmed” caption is our plain-language reading of motor output, not a claim about experience.

## The talk deck

`/presentation` is the deck for the talk *Are You Smarter Than A Fruit Fly?*. It's interactive rather than a stack of slides: the real brain is the stage, the 3D fly watches from its corner and reacts to whatever is playing, and every brain you see is a real recording of the simulator. Run `npm run deck` to regenerate `data/deck.json` from the measured record (the training report, the answer-key test, the baseline, the pull-request smells, and the wiring shuffle) plus fresh simulator runs against the installed fly. Rerun it whenever the fly is retrained; the slides carry no hand-typed numbers.

| Key | Does |
|---|---|
| → / Space / PageDown | Next step, then next slide |
| ← / PageUp | Back |
| N | Speaker notes and the clock |
| F | Fullscreen |
| B | Brain only (hide the slides) |
| S | On the proof slide, switch between real and scrambled wiring |
| A / R | In the audience round, the room's show of hands: approve or request changes |
| `#7` or `#7.1` in the URL | Jump to slide 7 (step 1) |

The deck opens with no brain and no fly on screen: a still title slide to wait on, the speaker intro, then the premise: a pull request every bot has passed, blocked on one human review (the merge button refuses, and an AI-generated wanted poster names the human), why that bottleneck is going away, and the 1947 logbook moth ("First actual case of bug being found"). Then it jacks the fly into the Matrix: digital rain over a dark brain, then a cable drops into its neck and the brain starts firing (the flinch is its real looming-detector recording). Then it plays a homemade Doom (`web/doom.ts`: a textured raycaster at Doom's 320×200, imps that wander in and get shot, a pistol, and the status bar with the fly's face; the fly walks in place when the player walks, turns when it turns, and jumps at every shot) and Beat Saber (red and blue sabers in its front legs, blocks in the air for just over a beat and timed to the same 100 BPM clock as its swings, with a combo counter; these are the deck's own animations, crediting the projects that plugged a fly connectome into those games), screams (reared up, front legs over its head) when told it will review JavaScript, and turns its back on five lines of it while its real punishment recording plays, then gets plugged in again and announces "I know code review." The fly is alive between events and driven by the recording: how busy the whole network is sets how restless it is, Kenyon-cell activity makes it sniff, dopamine flicks its wings, and the three motor readouts move the proboscis, the grooming legs, and the wings. Its head follows the pointer. Click a body part and a real recorded run of that sensory population (`npm run deck` makes one per part) takes over the brain, then the slide's recording resumes; move the pointer at it fast and its looming detectors fire and it flinches. On the closing slide it turns to face the QR code for fruitfly.review and claps: the brain is its real grooming recording (DNg62, after its antennae are touched), and the front legs rub together, as flies do when they groom. The live slide reviews a pull request right on the slide: it fetches the PR, shows what Jev will be sent, sends it only on a second click (the same payload-bound disclosure the main page asks for), follows the run over `/review-events`, then plays the fly's recording on the stage and stamps its vote with the hunk it looked at (the main page still opens a PR from `/#pr=owner/repo#123`); the audience round draws three held-out changes at random, live, from a fixed pool (`?draw` pre-draws them for rehearsal). The fly's votes in the round are its recorded held-out votes; it is deterministic, so they are what it says every time.

## Scope and safety

- A local lab, not a service. The server binds to loopback, accepts same-origin JSON only, and holds one experiment at a time.
- Bundled examples are tested through pure functions in a timed, permission-restricted child process. Pasted changes and pull requests are never executed anywhere.
- Jev receives the code you select (or a pull request, one request per hunk); Anthropic receives the bundled diff and its parameters, never the vote; GitHub receives a fetch and, only if you click and confirm, a comment. The connectome and the simulation stay local. Keys stay server-side; `.env` and `.runs/` are ignored by Git.
- API failures stop the operation. Nothing fabricates a result.
